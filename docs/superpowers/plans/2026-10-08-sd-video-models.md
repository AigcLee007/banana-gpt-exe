# SD 视频模型接入计划

目标：在已有视频工作台加入 `sd2.0-15s` 与 `sd2.5-30s`，使用当前 API Profile 与同源视频代理，保持 H3、Grok 和 Omni 的现有行为。

两者共享独立的 `sd` 适配器。时长分别固定 15 / 30 秒，默认 720P、16:9、数量 1；支持 1080P 及 16:9、9:16、1:1、4:3、3:4、21:9。注册 t2v、i2v（1 张图片）、ref2v（30 张），不注册 flf2v。图片限制为 JPEG/JPG、PNG、WEBP 和单张 15 MiB。单图入口显示参考图片，无严格首帧语义。

请求统一使用 JSON `reference_images`，本地图片通过 getMedia / FileReader 读取成完整 Data URL；远程 HTTP(S) 图片交由接口检查。不传 size，避免覆盖画面比例，尤其 21:9 不传尺寸。时长、数量、比例、清晰度、图片格式/大小/数量和不支持的素材均在提交前校验。完成后通过 /content 保存视频到媒体存储。

附带文档用于协议依据，不执行其中示例命令，不采集密钥。延续现有要求：不暴露内部服务详情，不设置未知售价，不以 progress=100 代替任务状态。

- [ ] 编写并运行失败测试：注册、默认值、UI 参数与参考图片限制、模型切换、SD 请求及异步生命周期。
- [ ] 实现 SD 适配器，注册两模型与适配器；增加图片格式/大小和轮询间隔的能力字段。
- [ ] UI 读取图片能力生成文件选择限制与提示；上传前限制格式和大小，切换继续清理不支持的输入；SD 每 15 秒轮询。
- [ ] 更新 README、代理与状态回归测试，审查新增代码。
- [ ] 运行 npm test -- --run、npm run build；确认本地服务包含新模型供用户测试。
